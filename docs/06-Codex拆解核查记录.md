## 三、不完整的地方（不是错，但不能当「已梳理完」）

- **元素级规格只有 4 张**（U01 U02 U03 U04）。其余 28 张只有索引里的一行描述。Codex 自己的阅读入口里也写了这一点，没有隐瞒。
- U15–U17（加工中）只被当作 U02 的补充，**没有单独展开**，所以「今天拍完了」「接着做」「先补再拍」「这两步不用你盯」等 10 个文案在它的文档里查不到（见 `05-功能清单-进项与加工中.md`）。
- **命名差异没标出来**：界面里（加工中队列、选题池、创作详情页）三处都写「**一勾式**骨架」，正文写「**一句式**骨架」。Codex 全程沿用正文写法，没提这个差异（我也是读完 U18 才放大发现的）。
- 没核的部分：`evidence-register.json`（50 KB 的证据登记）、Codex 自己的几份审查文档（02、06、08、10、12）、03 清单里「归属」和「缺口」两列的内容。

## 四、更正我之前对 Codex 的批评

我在 `开源仓库补证.md` 第 3 节批评 Codex，现在核实后，**下面几条是我说重了或说错了**：

| 我之前说 | 核实后 |
|---|---|
| 「漏了『为什么散』『引导』标签」 | **不对**。Codex 的 T16 记了七种标签（含「引导」），T27 记了「爆散原因」。「为什么散」「前 N 秒」是在开源代码里才有的，原文档里没有，它不可能写 |
| 「把能裁定的事挂成冲突」，如「想复刻」 | **说重了**。「想复刻」去哪，文字有三个来源，两个指向收藏、一个指向创作页，它保留为未裁定是对的，我的「可以裁定」没有证据 |
| 「C05：14 个组件和 157 张镜头卡是两个库」是它的缺陷 | **不对**。它的结论就是「分别视为组件机制与样例目录，不能认定为同一计数」，和我一致 |
| 「把 park-video-v2 的 9 步和 koubo 的 14 步混为一谈」 | **没有证据**。它写的是「U24 的步骤提示与 D05 的分组粒度不一致，不能直接认定一一对应」，很谨慎 |
| 「没查开源代码，很多待补证其实有答案」 | **对，但这是任务范围，不是错误**。你让它读两份文档，没让它查代码 |
| 「按截图组织，只做了 4 张」 | **对**，这是它最大的实际缺口 |
