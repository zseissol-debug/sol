# 02 数据契约

> 代码为准：`app/backend/studio/models.py`（Python）与 `app/frontend/src/types.ts`（TypeScript）一一对应。本文是给人看的说明，改字段时三处一起改。

## 原则

1. **一切围绕「选题」转**：日报条目、拆解报告都可以「入选题池」变成一条选题；后面的稿子、视频项目、发布记录都挂在选题上（第 3 期起）。
2. **来源可追溯**：每份日报、报告都标 `source`：`park_public`（Park 公开库，只读演示数据，原话版权归原作者）或 `local`（你自己生成的）。本地的永远不会被公开库同步覆盖。
3. **入池只带那一条**：从日报入池，放进去的是单条内容，不是整份日报（原版 U05 的明确规则）。
4. **缺就是缺**：拿不到的数字存 `null`，页面显示「—」，不拿 0 或估算代替（如新号不给倍数）。
5. **引擎可替换**：拆解引擎、日报引擎只通过适配层（`teardown_adapter.py`、`daily_adapter.py`）接入，产出统一转成下面的模型。以后作者开源新模块，或你想换实现，只改适配层。

## 对象

### 选题 Topic

| 字段 | 说明 |
|---|---|
| `id` | 10 位随机串 |
| `title` | 标题 |
| `origin` | `{kind: news \| report \| manual, ref, url}`；`ref` 对日报是 `日期:条目id`，对报告是视频 id |
| `excerpt` | 入池时带上的那一条的内容 |
| `stage` | 选题 → 提纲 → 录制 → 剪辑 → 待发 → 已发出 |
| `status` | `pool` 在池里、`scheduled` 已排期、`trash` 不做了（回收站，随时可拖回） |
| `created_at` / `updated_at` | ISO 时间 |

> 「阶段自动推断」的规则原版没写明，目前阶段由你手动改；第 3 期定规则。
> `scheduled` 状态已留好，排期日历在第 3 期做。

### 拆解报告 Report

对应 douyin-teardown 的 `report.json`（`schema_version 2`），字段如下。页面各区块与字段的对应：

| 页面区块 | 字段 |
|---|---|
| 标题、作者、「在抖音打开」 | `title` `author` `source_url` |
| 6 个指标格 | `facts`：`multiple_of_median` `likes` `collect_per_like` `share_per_like` `comment_per_like` `account_median_likes` |
| 主线（引号框） | `thesis`（`text` + `evidence`：秒数与原话，由程序从转写稿取，AI 改不了） |
| 色带与逐段卡片 | `segments[]`：`label`（钩子 / 承诺 / 论点 / 案例 / 跑题 / 收束 / 引导）、`start` `end`、`summary`、`reason`、`drift`、`text`（逐段原文） |
| 「跑题 N 秒 · 占 X%」 | `drift_seconds` `drift_share`（程序累加，不是 AI 估的） |
| 为什么爆 / 为什么散 | `why_boom[]` `why_scatter[]`，每条带 `evidence` |
| 前 N 秒（仅自己的视频） | `opening`：观众平均看到的前 N 秒听到了什么 |
| 底部蓝框 | `hypothesis_note`：结构标签和「为什么爆」是待验证的假设，不是爆款规则 |
| 归档 / 入池状态 | `archived` `topic_id` |

`facts` 里还可能有 `views` `comments` `shares` `collects` `account_post_count`，以及自己视频才有的 `creator_*`（完播率、5 秒完播、2 秒跳出、平均观看秒数、封面点击、涨粉）。

倍数口径：**点赞 ÷ 作者最近 60 条（不含置顶）的点赞中位数**。作者不到 20 条，或中位数不到 50 赞，不给倍数（`multiple_of_median` 缺失）。

### AI 日报 NewsIssue

```
NewsIssue { id=日期, title, source, brief_count, sections[] }
  NewsSection { kind: brief 快讯 | deep 深读 | radar 产品雷达 | other, title, groups[], text }
    NewsGroup { name?, items[] }          # 快讯按「底层工具 / 工作流 / 内容」分组
      NewsItem { id, title, url?, source?, summary, topic_id? }
```

同一份结构既能读 Park 公开 RSS 的 HTML，也能读本地引擎产出的 Markdown（`006_ai daily newsletter/YY-MM-DD.md`）。

### 任务 Job

`kind`：`teardown` / `newsletter`。`state`：`queued → running → done / failed`。
拆解任务的 `stage`：`downloading → transcribing → analyzing`（对应原版「N 个拆解进行中」）。
任务落盘；服务重启时仍在跑的任务会被标成失败（不会假装还在跑）。

## 存储

`app/data/`（已 gitignore）下一个对象一个 json 文件，原子写入：

```
data/reports/<视频id>.json     data/newsletter/<日期>.json
data/topics/<id>.json          data/jobs/<id>.json
data/teardown/                 拆解引擎自己的产物（报告 json/md、下载缓存、基线缓存）
data/park-io/                  日报引擎的数据根目录
```

计划：第 3 期把选题与稿子再导出成 Markdown 存进 Obsidian vault（原版「存一份进原始输出」）。

## 接口

`/api/docs` 有完整的交互文档（服务启动后打开）。主要几组：

| 路径 | 作用 |
|---|---|
| `GET /api/newsletter/issues`、`/issues/{日期}` | 日报列表与详情（详情里标出已入池的条目） |
| `POST /api/newsletter/sync` | 拉取 Park 公开日报；`POST /generate` 本地生成 |
| `POST /api/newsletter/issues/{日期}/items/{条目}/topic` | 单条入选题池（幂等） |
| `GET /api/reports`、`/reports/{id}`；`PATCH` 归档 | 报告列表 / 详情 / 归档 |
| `POST /api/reports/sync-public`、`/reports/{id}/topic` | 导入公开拆解库、报告入池 |
| `POST /api/teardown` `{url}` | 拆一条抖音链接（只收抖音域名；同时最多 3 条） |
| `GET /api/teardown/env` | 拆解环境检查（与 `teardown doctor` 同口径） |
| `GET/POST/PATCH/DELETE /api/topics` | 选题池 |
| `GET /api/jobs`、`/jobs/{id}` | 任务状态 |
