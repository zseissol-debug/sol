## 3. 账号卡片网格（U07）

本图共 **12 张卡 + 1 张添加卡**（4 列 × 3 行；U01 是 11 张）：7 个「对标」+ 5 个「老师」。

| 元素 | 原版 |
|---|---|
| 角色标签 | 「对标」灰色 / 「老师」蓝色；**点它切换** |
| 账号名（粗体）、粉丝数（灰字，如「50万 粉」）、右上「×」 | 有；「×」含义未实测（移除关注？） |
| **走势图**：折线 + 浅蓝面积 + 一条水平虚线 + 若干**金色圆点** | 每个点是一条作品的点赞；虚线应是该账号的点赞中位数；金点应是**超过爆款门槛**的作品（**推断**：金点数 ≈ 卡片上「爆款 N」） |
| 三个统计：「中位 2,217」「作品 60」「爆款 11」（爆款数为金色） | 有 |
| 「9 小时前同步」 | 上次同步时间；U07 里有的卡没有（如 Xuan酱一行只有同步时间） |
| 两个按钮：「同步」「主页 ↗」 | 单号同步；打开账号主页 |
| 添加卡：虚线框 + 「+ 加一个老师或对标」+ 「抖音 · 小红书 · X · 视频号」 | 点了弹出 U08 |
| 部分账号名很长时截断（「小胡也是小狐（十月线下课」） | 有 |
| 卡片间同一行的统计数字对不齐 | 无需复刻（原版也是内容高度不同） |

对账：卡片上的「中位 / 作品 / 爆款」统计，对应开源代码里倍数基线的「近 60 条非置顶点赞中位数」；**「作品 60」恰好等于 60**，说明基线取的就是最近 60 条（**码**：`baseline.py` 拉 3 页 × 20 条）。

## 5. 爆款样本列表（U09）

| 元素 | 原版 |
|---|---|
| 区块标题「爆款样本 18 条 · 更早的 127 条在「全部」里」 | 18 = 当前筛选（30 天、爆款）命中数；127 = 更早的 |
| 右上图例「互动结构：■收藏 ■转发 ■评论（相对点赞）」 | 绿 / 蓝 / 紫三色 |
| 每行左：大号金色倍数「32.7×」+ 小字「中位倍数」 | 倍数 = 该条点赞 ÷ 该作者中位数 |
| 每行中：标题（粗体）+ 灰字「作者 · 9/22 · 21:43」（时长） | 有 |
| 每行右：「赞 8,196 / 收藏 4,170 · 转发 2,763」三个绝对数 | 有 |
| 每行右：**三色横条** + 小字「评论型 · 收藏 50.9%」 | 条的三段长度 = 收藏、转发、评论各占赞的比例；类型标签有：**评论型 / 点赞型 / 收藏型 / 收藏+转发**；后面的百分比是收藏/赞 |
| 蓝色按钮「看报告」 | 点了进「拆解报告」 |
| 排序按倍数从高到低（32.7× 9.4× 8.3× 5.7× 4.0× 4.0× 3.6×…） | 与「按倍数」一致 |

类型标签怎么判定：原版没写。我从数据能看出规律（**推断**）：「评论型」的评论占比最大，「点赞型」是三者都不突出，「收藏型」收藏/赞最高，「收藏+转发」两者都高。阈值需要你定。

## 6. 与 Codex 的 U01 规格对账

| 项 | 结果 |
|---|---|
| U07 / U01 是同一个页面的两次截图（滑杆 2.5× vs 4×；30 天 vs 这一周；12 张卡 vs 11 张） | Codex 判断「另一图示状态」是对的；它不能确定版本先后也合理 |

## 7. 实现依据（开源代码）

| 功能 | 依据 |
|---|---|
| 中位数、倍数、小样本不给倍数 | `douyin-teardown/baseline.py` + `structure.py` ✓ |
| 每个号只读最新一页、撞风险就停 | `daily-newsletter/ingestion/douyin/run.py`、`baseline.py` ✓ |
| 走势图、金点、爆款数、同步时间 | 无开源实现，要自己做（数据来源就是抓到的每条作品点赞） |
| 添加账号的链接解析（抖音 `sec_uid`） | `daily-newsletter/ingestion/douyin/run.py` 里的 `sec_uid_from_url`（取主页链接最后一段）✓；`douyin-teardown` 的下载器按 `sec_uid` 拉作者作品 ✓ |
| 小红书、X、视频号主页同步 | 无证据 ❌ 弹窗只承诺抖音 |
