# 09 功能清单（设计文档）· 加工中 Phase 3

> 范围：U15-U17，加工中页面的核心功能实现。参考：docs/05 第 4、6、8 节。
> 状态：PRD 设计阶段，待对抗性审查。

---

## 概览

### 业务目标
实现「加工中」页面，让用户能：
1. 从选题池里选一条，设为「正在做的这一条」（焦点卡）
2. 看到这一条的进度（6步：选题→提纲→录制→剪辑→待发→已发出）
3. 进入创作详情页，一步步完成（你说一遍 → 骨架 → 付息稿 → 剪辑进度）

### 页面构成
```
加工中（左侧栏）
├─ 选题池列表（37 条）[左栏]
│  ├─ 系列卡片（未做，依赖规则定义）
│  └─ 选题行（阶段 · 标题）
│
├─ 焦点卡 + 6 步进度条（中间）[右上]
│  ├─ 标题
│  ├─ 6 步进度条（选题 → 提纲 → 录制 → 剪辑 → 待发 → 已发出）
│  ├─ 提示语（根据阶段和 QA 结论显示）
│  └─ 3 个按钮：打开、退回提纲、放回选题池
│
└─ 接下来拍队列（日期 + 标题） [右下]（未做）
```

## 1. 左栏：选题池列表

### 1.1 列表头

| 元素 | 说明 |
|---|---|
| 标题 | 「选题池 N」，N = pool 状态的选题数 |
| 说明 | 「从『进项』、拆解报告或你建的系列进来」（原版 U15） |
| 「+ 建系列」按钮 | 新建系列（Phase 3 不做，留作 Phase 4） |

### 1.2 选题行（重点）

每行显示一条选题，**可点击选中**（变成右上的焦点卡）。

| 字段 | 显示内容 | 数据来源 | 备注 |
|---|---|---|---|
| 阶段 | ◯ 或 ● 符号 + 文字 | `topic.stage` | 6 个阶段用不同符号；当前进度的阶段用 ◯（空心），已完成用 ●（实心） |
| 标题 | 文本 | `topic.title` | 可带序号（如「1. 怎么…」），原版有 |
| 日期标签（可选） | 「今天拍」/ 「明天拍」/ 「周三 10/7 拍」 | 规则定义（Phase 4） | 现阶段先不显示 |
| 状态文字（可选） | 「还没说」/ 「已说」 | 规则定义（Phase 4） | 现阶段先不显示 |
| 不做了 | 点了变灰，移到回收站 | `topic.status` → `trash` | 原版有，保留 |

### 1.3 交互

- **点击选题行** → 选中，右上焦点卡更新（该条数据）
- **点「不做了」** → 状态变 `trash`，行变灰，可选择是否从列表消失（现在消失，回收站功能 Phase 4）
- **拖拽排序**（原版有）→ Phase 4，现在不做

## 2. 右上：焦点卡 + 6 步进度条

### 2.1 页头区域

| 元素 | 说明 | 数据 |
|---|---|---|
| 返回链接 | 「← 加工中」 | 路由 |
| 标题 | 选题的标题 | `topic.title` |
| 「不做了」按钮 | 灰色 | 状态 → `trash` |

### 2.2 6 步进度条（核心）

```
选题 → 提纲 → 录制 → 剪辑 → 待发 → 已发出
 ◯      ◯     ◯     ◯      ◯       ◯
```

| 属性 | 实现 |
|---|---|
| **当前阶段** | 显示 ◯（空心圆）+ 橙色 |
| **已完成阶段** | 显示 ●（实心点）+ 灰色 |
| **可点击** | 是。点击阶段 → `topic.stage` 变更（**手动改，不用推断**） |
| **数据来源** | `topic.stage` 值 |

### 2.3 进度提示语

点击进度条下方显示的说明文字（橙色加粗小字），**随阶段和 QA 结论变化**。

| 阶段 | 正常提示 | 有问题提示 |
|---|---|---|
| 选题 | 「选好题，下一步说一遍」| — |
| 提纲 | 「你说一遍 → 骨架 QA 评分」 | 「素材太薄，先补再说」（QA 结论 = thin） |
| 录制 | 「骨架已过，可以录口播了」| 「骨架未通过，先回到提纲」|
| 剪辑 | 「录好了，开始剪」 | — |
| 待发 | 「剪好了，等发布」 | — |
| 已发出 | 「已发布」 | — |

**注**：QA 结论（go / patch / thin）由稿子审查产生，Phase 3 先写死，后续与引擎对接。

### 2.4 焦点卡的三个按钮

| 按钮 | 功能 | 路由 / 状态变更 |
|---|---|---|
| **打开**（蓝色） | 进入创作详情 | 路由 → `/working/{topic_id}` |
| **退回提纲** | 如果当前阶段 > 提纲，回到「提纲」 | `topic.stage` → 「提纲」 |
| **放回选题池** | 把焦点卡清空，回到列表选其他 | 焦点卡隐藏，列表恢复可选 |

## 3. 创作详情页骨架

### 3.1 页面结构

```
创作详情
├─ 页头
│  ├─ 返回「← 加工中」
│  ├─ 标题（选题标题）
│  ├─ 「不做了」按钮
│  └─ 5 步进度条（骨架 → 录制 → 剪辑 → 待发 → 已发出）
│     【注】与加工中的 6 步不同：这里「选题、提纲」合并为「骨架」
│
├─ 四个 Tab（按显示顺序）
│  1️⃣ 你说一遍
│  2️⃣ 骨架
│  3️⃣ 付息稿
│  4️⃣ 剪辑进度
│
└─ 每个 Tab 的状态小字
   （未做时无字；做过后显示「已存」/「已写」/「已关联」）
```

### 3.2 Tab 1: 你说一遍

| 部分 | 内容 |
|---|---|
| **左栏** | 来源拆解的完整「主线结构」（引文 + 色带 + 图例 + 逐段摘要）；复用拆解报告页的组件 |
| **右栏** | 文本框 + 自动保存（本地 `localStorage`） |
| **右栏标题** | 「看着左边的拆解，直接说」 |
| **右栏说明** | 「用电脑的语音输入法往这里说，说的都是你自己的经历和判断。边说边存，刷新不丢。」 |
| **右栏操作** | ❌ 先不做「删口水话」；✅ 做「标题」输入框（预填选题标题，可编辑，debounce 自动更新 topic.title） |
| **存储流程** | ① 输入时自动 debounce 保存到本地 localStorage（草稿）②  点「保存」→ POST `/api/topics/{id}/spoken-text` 将文本存到数据库的 `topic.spoken_text` 字段③  后续可选：同步到 Obsidian（async，失败不阻塞） |
| **Tab 状态** | `topic.spoken_text` 非空 → 显示「已存」 |

### 3.3 Tab 2: 骨架（简化版）

| 部分 | 说明 |
|---|---|
| **页首** | 「一勾式骨架 · 生成于 XX · 最后修改 XX」 |
| **QA 评分** | 红标（thin/patch/go）+ 分数「X/15」+ 「评估 / 重评」按钮；**现在写死默认值**，后期与引擎对接 |
| **骨架正文** | Markdown 文本，支持「预览 / 编辑」切换 |
| **开头候选** | 5 条，每条「开头句 （手法 · 原话「…」）」；**原话由程序取（从拆解引文里）**，AI 不能编 |
| **复制 / 重写** | 按钮存在，现阶段功能先留空 |
| **证据** | 【Phase 4】先不做「按论点找证据」，仅显示占位文字 |
| **Tab 状态** | 「已写」 |

### 3.4 Tab 3: 付息稿（简化版）

| 部分 | 说明 |
|---|---|
| **标题** | 同骨架 |
| **结构** | 「本金」段 + 「发债」段 + 「第 1 笔息」… + （可选）「还本」段 |
| **内容** | Markdown 正文；**不需要四列表**，先就是一段段的文本 |
| **状态** | 「已写」 |

### 3.5 Tab 4: 剪辑进度

**两种状态**：未关联 vs 已关联

#### 3.5.1 未关联状态

| 卡片 | 内容 |
|---|---|
| **左卡** | 「新建项目文件夹」+ 说明 + 橙色按钮「新建并关联」 |
| **右卡** | 「关联已有项目」+ 下拉框（读 `video_projects_root` 里的文件夹）+ 按钮「关联」 |

#### 3.5.2 已关联状态

| 元素 | 显示 | 技术细节 |
|---|---|---|
| **项目名** | `日期_标题`（如「2026-10-05_怎么让AI…」） | 来自 `topic.video_project_path` 的文件夹名 |
| **完整路径** | `/Volumes/Phone SSD/视频/exports/2026-10-05_…` | `topic.video_project_path` 的值，POST 关联时保存 |
| **按钮** | 「刷新」「取消关联」 | 刷新 → 重新读文件系统检查项目状态；取消 → 清空 `topic.video_project_path` |
| **黄边提示卡** | 「要你动手 · 还没按 14 步初始化」+ 按钮「初始化」（补 `project.json`） | 检查项目文件夹下是否存在 `project.json` |
| **状态行** | 「● 0 分钟前还有写入 / 最后写入：…」（监测文件修改时间） | 实时读文件系统的修改时间戳 |
| **Tab 状态** | `topic.video_project_path` 非空 → 显示「已关联」 | — |

## 4. 数据结构变更

### 4.1 Topic 模型（backend/studio/models.py）

**现状**（models.py:132）：
```python
class Topic(BaseModel):
    id: str
    title: str
    origin: TopicOrigin
    excerpt: str = ""
    stage: Literal["选题", "提纲", "录制", "剪辑", "待发", "已发出"] = "选题"
    status: Literal["pool", "scheduled", "trash"] = "pool"
    created_at: str
    updated_at: str
```

**需要添加**（Phase 3 用到的字段）：

| 字段 | 类型 | 用途 | 备注 |
|---|---|---|---|
| `focal` | `bool` | 是否是焦点卡的那一条 | 默认 false；同时只有 1 条是 true；由 POST `/api/topics/{id}/set-focal` 修改 |
| `scheduled_date` | `Optional[str]` | 排期日期（ISO 8601） | Phase 4；现在先留空 |
| `qa_conclusion` | `Optional[Literal["go", "patch", "thin"]]` | QA 评分结论 | 默认值 "go"；前端显示为「满分 15」 |
| `spoken_text` | `Optional[str]` | 「你说一遍」的口述内容 | localStorage 本地草稿 → 点保存才写到此字段；关键：改了标题框也要自动更新 topic.title |
| `video_project_path` | `Optional[str]` | 关联的剪辑项目完整路径 | 如 `/Volumes/Phone SSD/视频/exports/2026-10-05_…` |

**需要的关联数据**（不需要存 Topic，但查询时需要拼）：

- `report_id` → 来自 `origin.ref`，用来在创作详情页左栏显示拆解
- `created_at` 的修改时间 → 显示在选题行上（「今天拍」/「明天拍」）

### 4.2 前端 types.ts 变更

同步上述字段到 `Topic` 接口。

## 5. API 接口需求

### 5.1 现有接口的改动

| 端点 | 现状 | 需要改 | 说明 |
|---|---|---|---|
| `GET /api/topics` | 返回所有 pool 状态选题 | ✅ 根据 `focal` 字段高亮当前选中 | 检查响应中哪一条 focal=true |
| `PATCH /api/topics/{id}` | 更新选题 | ✅ 支持更新 `stage`、`title`、其他字段（**除 focal，focal 只通过 POST set-focal 改**） | 标题编辑时通过此接口 debounce 更新 topic.title |
| `DELETE /api/topics/{id}` | 删除（物理删除） | ✅ 改为逻辑删除：`status` → `trash` | 前端「不做了」按钮触发 |

### 5.2 新增接口（必需）

| 方法 | 端点 | 功能 | 说明 |
|---|---|---|---|
| POST | `/api/topics/{id}/set-focal` | 设置焦点卡 | 原子操作：清空其他 focal=true 的选题，设置这条为 focal=true |
| GET | `/api/topics/{id}/with-report` | 获取选题 + 关联报告 | 返回选题完整信息 + 拆解报告数据（用于创作详情页左栏） |
| POST | `/api/topics/{id}/spoken-text` | 保存「你说一遍」 | 将口述内容写到 `topic.spoken_text` 字段；前端先本地 localStorage |

## 10. Phase 3 已确定的决策

1. ✅ **QA 评分**：Phase 3 硬编码默认 `qa_conclusion = "go"`，前端显示「满分 15」；后期与引擎对接
2. ✅ **「你说一遍」存储**：localStorage 本地草稿 → 点保存写到 `topic.spoken_text` 字段；Obsidian 同步留作 Phase 4
3. ✅ **焦点卡 API**：统一用 POST `/api/topics/{id}/set-focal`，PATCH 不改 focal 字段
4. ✅ **标题编辑**：右栏标题框 debounce 自动更新 `topic.title` 和焦点卡（不用点保存按钮）
5. ✅ **剪辑项目路径**：关联时保存到 `topic.video_project_path` 字段

## 11. Phase 4+ 决策点（暂不做）

1. **排期机制**：怎样给选题排期？用 `topic.scheduled_date`，交互方式 Phase 4 定
2. **口水话词表**：「删口水话」功能，Phase 4 定义词表后做
3. **系列规则**：建系列后的自动生成逻辑，Phase 4 定用户规则后做
4. **Obsidian 同步**：「你说一遍」保存后是否自动导出到 Obsidian，Phase 4 接入 vault API
